## Exhibits

These exhibits show only structural evidence: stored time fields, build settings and the shape
of the embedded path. Persona names, handles, the workstation account name, mailbox values and
provider-account identifiers are redacted or left out of every excerpt. ZIP times were read
with `TZ=UTC` so that the analyst's own timezone cannot enter the comparison.

### Exhibit E12-1. Windows-agent archive: local DOS time vs UTC extended time (UTC−4)

Artifact: Windows Node agent archive (win_node_agent.zip) · 603347 bytes · SHA-256 `be5859f23f0781242d854dc24c102c694dabfc14a159b56429e313f0521141b6`
Location: central-directory entry `lib/server-resolve.js` (local header at offset 550020)
Extraction: `TZ=UTC zipinfo -v win_node_agent.zip lib/server-resolve.js | grep "^  lib/\|file last modified"`
Supports: "approximately UTC−4 for one Windows-agent archive"

```text
  lib/server-resolve.js
  file last modified on (DOS date/time):          2026 Jul 13 02:13:14
  file last modified on (UT extra field modtime): 2026 Jul 13 06:13:14 local
  file last modified on (UT extra field modtime): 2026 Jul 13 06:13:14 UTC
```

The DOS field (02:13:14) is four hours behind the UTC field (06:13:14). The "local" line is
zipinfo's rendering of the UTC field in the reader's timezone (UTC here), not the creator's.
All 192 entries carry the UTC field (`TZ=UTC zipinfo -v win_node_agent.zip | grep -c "UT extra
field modtime): .* UTC"` returns 192).

### Exhibit E12-2. VSIX and nested agent archive: the same comparison gives UTC−7

Artifact: VSIX package (google-update-support.vsix) · 17647582 bytes · SHA-256 `52886aab179f26421678ff23af1b0fabf0a17ffbb534369cdbbac8008cbed8e7`
Artifact: Nested native-agent archive (google-update-support-agent.zip) · 17283435 bytes · SHA-256 `e1bf1b29e6fa3525d7f32f429290a88d6ea2890e61c06574b8ff6372aa5d0667`
Location: VSIX entry `extension/extension.js`; nested entry `google-update-support-darwin-arm64`
Extraction: `TZ=UTC zipinfo -v google-update-support.vsix extension/extension.js | grep "^  extension\|file last modified"; TZ=UTC zipinfo -v google-update-support-agent.zip google-update-support-darwin-arm64 | grep "^  google\|file last modified"`
Supports: "UTC−7 for the VSIX and nested native-agent archive"; two-second DOS precision

```text
  extension/extension.js
  file last modified on (DOS date/time):          2026 May 12 22:10:42
  file last modified on (UT extra field modtime): 2026 May 13 05:10:41 local
  file last modified on (UT extra field modtime): 2026 May 13 05:10:41 UTC
  google-update-support-darwin-arm64
  file last modified on (DOS date/time):          2026 May 12 22:10:40
  file last modified on (UT extra field modtime): 2026 May 13 05:10:39 local
  file last modified on (UT extra field modtime): 2026 May 13 05:10:39 UTC
```

The difference is seven hours plus one second in both entries: DOS times are stored at
two-second resolution and round up from the odd UTC second, which is the small apparent
discrepancy the report mentions. The nested archive is the member extracted from the VSIX.

### Claims without a retained primary artifact
