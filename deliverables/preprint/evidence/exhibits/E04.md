### Claims without a retained primary artifact

- "Successful AES-GCM authentication for all three payloads": per the brief's static-only rule,
  decryption was not re-run here, so the authentication-pass result remains a reported case
  result. It is strongly corroborated by the retained plaintext payloads (E04-3/4/5), whose
  SHA-256 values match the report exactly, and by the key-assembly and blob-layout code (E04-1/2).
- "The two delivery vectors use different keys": the ClickFix-chain key is documented in another
  incident's report, not reproduced here; only the VSIX-vector key expression is a local artifact.

### Encrypted-copy identity

The retained encrypted copies differ: the `.enc` blobs inside the VSIX
(the extracted extension's `*.enc` files) and the separately held `*.enc` copies have different
SHA-256 values despite decrypting to the same plaintext — consistent with AES-GCM using a fresh IV
per encryption. The report says the payloads are "present both inside the VSIX and beside it," which
does not assert byte-identity.
